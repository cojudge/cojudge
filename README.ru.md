# Cojudge на русском

Локальная версия Cojudge: русский интерфейс, 1031 переведённая задача и оригинальные английские условия. Основа — Cojudge 0.8.11; изменения оригинала объединены с русской локализацией.

## Запуск

Нужен Docker с Linux-контейнерами. Выполните в каталоге проекта:

```sh
docker compose up -d --build
```

Откройте http://localhost:5375/ . Для проверки Python-решений нужны оба образа:

```sh
docker pull python:3.11-slim
docker pull alpine/java:22-jdk
```

Java используется проверяющей системой в том числе для Python. Для переноса без интернета сохраните три образа через `docker image save`, загрузите их на сервере через `docker image load`, затем запустите Compose с `--no-build --pull never`.

## Имена образов

В `.env` рядом с `compose.yaml` или в переменных стека Portainer задайте:

```dotenv
COJUDGE_PYTHON_IMAGE=python:3.11-slim
COJUDGE_JAVA_IMAGE=alpine/java:22-jdk
```

Можно указать другие теги совместимых образов. Они должны быть доступны Docker, к которому подключено приложение. После изменения переменных пересоздайте контейнер: `docker compose up -d --no-build --force-recreate`. Пересборка приложения не нужна.

## Данные

Прогресс хранится отдельно в браузере каждого пользователя. Для переноса используйте экспорт и импорт прогресса в интерфейсе. Серверных аккаунтов и общей базы прогресса нет. Задачи и курсы сохраняются в томе `cojudge-content`. При запуске обновляются только неизменённые пользователем файлы из поставки.

Английские оригиналы находятся рядом с переводами: `statement.en.md`, `metadata.en.json`, `courseinfo.en.json`. На странице задачи есть переключатель оригинала. SQL не поддерживается.

Приложение запускает контейнеры решений через `/var/run/docker.sock`; доступ к этому сокету даёт управление Docker на сервере. Это подключение требуется для проверки решений.

Переводы и изменения восстановлены из кэша последней успешной Docker-сборки. Ветка `restore/cojudge-ru` включает обновления оригинала до версии 0.8.11. Обновлённые задачи на реализацию классов переведены с сохранением новых шаблонов и тестов.

## Обновление из оригинала

Сначала сохраните свои изменения коммитом. Затем в ветке с локализацией выполните:

```sh
git fetch upstream
git merge upstream/main
```

При конфликтах сохраняйте новые сигнатуры, шаблоны и тесты оригинала, а переводы адаптируйте к изменённым условиям. Обновляйте также английские копии `statement.en.md` и `metadata.en.json`. После разрешения конфликтов выполните `git add .`, `git commit`, проверьте сборку и отправьте ветку через `git push`.
