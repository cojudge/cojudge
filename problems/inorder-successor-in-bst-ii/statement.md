Двоичное дерево поиска хранит попарно различные значения с обычным упорядочением: все в левом поддереве меньше узла, все в правом поддереве больше.В классическом последующем каждый узел также знает своего родителя, поэтому преемник может быть найден только из целевого узла, идя вниз и вверх.

** Ссылки на родителей не могут проходить через ценностный интерфейс этого судьи, поэтому дерево передается явно вместе со своими родительскими ссылками: `root` Сериализация по упорядочению (с) `null` Пробелы, например. `"[2,1,3]"`), `parents` Кодирует одно родительское значение на не-`null` вступление `root` в том же порядке слева направо (`null` для корня дерева, и `p` - это значение целевого узла. `root = [2,1,3]` пары с `parents = [null,2,2]` потому что узлы 1 и 3 У обоих есть родитель 2Восстановите родительские ссылки из этой пары, а затем отвечайте точно так же, как и родительская версия.

Учитывая эту кодировку и целевое значение `p`, присутствующее в дереве, возвращайте значение узла, посещенного сразу после `p` в порядке. Возвращайте `-1`, когда `p` является наибольшим значением (или когда дерево пусто / `p` отсутствует).

**Ограничения:**
- `0 <= number of nodes <= 10^4`
- `-10^5 <= Node.val <= 10^5`
- Все значения уникальны; дерево является действительным двоичным деревом поиска.
- `parents` имеет одну запись на ненулевое значение `root` в порядке соответствия
